# IK 配置是如何得到的

`skeleton_retarget/retargeting/ik_configs/skeleton17_collision/<动作名>.json` 描述“怎样把这套 LAFAN1 人体骨架的位姿目标，交给当前 MJCF 模型去跟踪”。它是模型适配的关键参数，实际求解还依赖 MJCF 的运动学结构、IK 算法和约束。官方对表项格式的说明见 [GMR DOC.md](../third_party/GMR/DOC.md)；下面说明本工作区自己的生成方法。

## 当前配置的来源

生成过程由 [`prepare_skeleton17.py`](../skeleton_retarget/scripts/prepare_skeleton17.py) 和 [`skeleton_retarget/retargeting/calibration.py`](../skeleton_retarget/retargeting/calibration.py) 实现。批处理调用 `calibrate_existing_model()`，对每条 BVH 写出配置和 `skeleton_retarget/retargeting/ik_configs/skeleton17_collision/references/<动作名>.json` 标定依据，共用同一份模型资源。没有修改官方配置或代码，也没有用神经网络学习 JSON：

1. **人工指定语义对应关系。** `BODY_MATCHES` 将 MJCF 的骨盆、大腿、小腿、后足、躯干映射到 BVH 的相应骨骼，共 8 对。例如 `calcn_l → LeftFootMod`。本模型的手臂固定，因此没有手臂跟踪任务。映射的是 body 位姿，不是直接把一个 BVH 关节角复制给某个 MJCF 关节。
2. **从 BVH 骨架构造人体参考姿态。** `lafan1_source_reference()` 读取骨骼层级和 offsets，统一厘米到米、Y 向上到 Z 向上，并显式构造解剖学中立 T 姿态。这一步不用动作第一帧。LAFAN1 的很多骨骼 offset 沿局部 +X，全部旋转清零并不等于正常站立，所以需要明确设置中立旋转。`FootMod` 的位置取自 Foot，朝向取自 Toe，与动作读取器一致。
3. **从 MJCF 求模型参考姿态。** `target_reference()` 在模型真实 `qpos0` 上执行 `mj_forward`，得到这 8 个 body 的世界位置和旋转。当前模型根旋转为单位旋转，关节为零位，保留其固定手臂。
4. **自动求缩放和坐标偏置。** `calibrate()` 根据两套参考姿态计算 `human_scale_table`、位置偏置和旋转偏置，让变换后的人体参考目标与模型参考 FK 对齐。根尺度取参考骨盆高度之比，其他 body 尺度取“该 body 到骨盆的距离”之比；这些不是直接逐骨段长度相除。
5. **人为给定任务权重。** 当前规则让脚的位置跟踪权重较大，骨盆次之，躯干主要跟踪朝向。两阶段使用不同权重。这些权重是适配时设计的取舍，后续可根据误差、脚滑与碰撞报告调整，并非静态标定自动发现的最优值。
6. **验证并记录来源。** `calibration_errors()` 检查变换后的人体中立参考与模型参考是否一致。模型准备还记录 BVH、MJCF、网格和配置的哈希。参考姿态上误差接近零，只能说明坐标标定自洽；运动中的可达性、脚滑和碰撞仍需逐条验证。

模型本体不变时可以共用一份 MJCF。不同 BVH 的人体骨架 offsets 可能不同，因此逐 BVH 重新生成配置最稳妥；若两条数据的骨架 offsets 和坐标约定完全相同，得到相同配置是正常的。动作窗口、120 Hz、速度倍率不改变静态标定本身。

## JSON 各字段的含义

| 字段 | 作用 |
| --- | --- |
| `robot_root_name` / `human_root_name` | 当前为模型 `pelvis` 与 BVH `Hips`，用于根对应与相对缩放。 |
| `human_height_assumption` | 与读入器给出的源身高共同决定额外尺度。当前 LAFAN1 读入器和配置均用 1.75，额外倍率为 1；真实比例已由 offsets 标定。 |
| `human_scale_table` | 按根及各目标 body 缩放人体位置，使目标更符合模型比例。 |
| `ground_height` | IK 目标中的地面偏置参数。当前为 0；本流程最后还根据真实脚碰撞盒调整根高度。 |
| `use_ik_match_table1/2` | 是否执行第一/第二组跟踪任务。 |
| `ik_match_table1/2` | 目标 body 的源骨骼、位置/朝向权重、局部位置偏置和旋转偏置。 |

每个表项的结构为：

```text
"MJCF body 名": [
  "BVH 源骨骼名",
  位置跟踪权重,
  朝向跟踪权重,
  [局部位置偏置 x, y, z],
  [旋转偏置 w, x, y, z]
]
```

例如第二阶段的左脚：

```json
"calcn_l": [
  "LeftFootMod",
  200,
  40,
  [-0.1574312647169583, -0.01972132695646142, 0.00675627083490607],
  [-0.7071067811865476, 0.7071067811865475, 7.850462293418875e-17, -7.850462293418876e-17]
]
```

这个数值示例来自 `walk3_subject3.json`。意思是让模型 `calcn_l` 跟踪经过标定的 `LeftFootMod` 目标，位置和旋转任务成本分别为 200、40。位置偏置单位为米，表示在**修正后目标朝向的局部坐标系**中的偏移，实际会随目标旋转转换到世界系；旋转偏置与源旋转右乘。配置四元数顺序为 **wxyz**，导出 NPZ 的 `root_rot` 则为 **xyzw**。

权重为 0 表示忽略该项误差，非零权重表示优化时的取舍。较大权重不会把目标变成硬约束，也不能保证脚严格不滑。两张表是依次执行的两轮加权求解；第二阶段会继续改变姿态，第一阶段目标并没有因此成为不可破坏的优先级。

若用 `p` 表示位置、`R` 表示旋转，运行时目标大致是：

```text
R目标 = R人体 × R偏置
p目标 = s根 × p人体根
      + s该骨骼 × (p人体该骨骼 - p人体根)
      + R目标 × p局部偏置
```

这里解释的是当前 `ground_height=0`、额外身高倍率为 1 时的标定。IK 随后寻找模型根位姿和关节角，使模型 FK 接近这些目标。

## 它与 MJCF、IK 求解器的分工

| 部分 | 决定什么 |
| --- | --- |
| MJCF | 能动哪些关节、关节轴/顺序/限位、body 层级/尺寸、膝锁、碰撞形状等。 |
| IK JSON | 跟踪哪些人体目标、如何映射比例与坐标、如何权衡各部位误差。 |
| `skeleton_retarget/retargeting/motion_retarget.py` | 将目标构建为 Mink FrameTask，通过两阶段 IK/QP 求姿态，并应用模型限位与启用的等式约束。 |
| `skeleton_retarget/retargeting/collision_ik.py` | 新模型的跨腿碰撞约束、实际几何间隙检查、非线性步长回退。 |
| `skeleton_retarget/scripts/bvh_to_skeleton17.py` | 时间窗口、120 Hz 重采样、输出帧关节增量限制、插值避碰修正、脚盒根高度调整和数据导出。 |

因此，JSON 是“人体与模型如何匹配”的核心配置，完整重定向方法由这些部分共同组成。修改 JSON 无法替代错误的关节轴或模型结构，也不能单独保证动力学可跟踪。17 个活动自由度来自 MJCF 的 21 个 hinge 减去 4 个膝锁；JSON 中的 8 对 body 任务数量与活动自由度数量没有一一对应关系。

## 什么时候需要重新标定

- 换目标模型、关节/body 坐标轴、参考姿态、body 层级或骨架尺寸：重新生成配置，并验证新动作。
- 换 BVH 骨架、人体比例、源数据格式或坐标约定：重新生成配置，必要时更新源读取器和 body 映射。
- 同一套人体骨架只换动作区间、输出帧率或速度：静态标定可以复用，但重新导出的动作仍要验证。
- 只改网格外观/颜色，且 body 运动学完全一致：通常可复用；若碰撞形状也改了，要重新检查几何和现有轨迹，即使静态配置仍可用。
- 只调任务权重：不需要重算参考 offsets，但要重新求解才能让新权重作用于动作。

新增模型或重新标定时先确认静态参考对齐，再检查动态跟踪误差、限位、膝锁、地面与跨腿间隙，最后回放。一次静态零误差不能替代这些动作检查。
